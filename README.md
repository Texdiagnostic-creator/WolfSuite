# WolfSuite — лаунчер и серверный тул для 7 Days to Die

Два самостоятельных приложения на C# (WinForms, .NET Framework 4.8, встроенный в Windows
`csc.exe`). Без установки SDK, без NuGet, без внешних DLL.

## Что кому

| Папка | Для кого | Файл |
|---|---|---|
| `dist\WolfServer\` | админ сервера | `WolfServer.exe` + `README.txt` |
| `dist\WolfLauncher\` | игроки | `WolfLauncher.exe` + `README.txt` |

Раздавать игрокам нужно **только папку `dist\WolfLauncher`** — один `.exe` и инструкция.
Серверная папка остаётся на машине с выделенным сервером.

## Структура проекта

```
WolfSuite\
  build.bat            сборка: dist\WolfServer, dist\WolfLauncher, bin (тесты)
  assets\              wolf.ico (иконка обоих exe), banner.jpg (баннер шапки лаунчера)
  src\Common\          общий слой, вкомпилируется в оба exe:
                         Json.cs           парсер/сериализатор JSON
                         GamePaths.cs      поиск Steam, игры, сервера, миров
                         ChunkStore.cs     чанковое хранилище по SHA-256
                         ModManifest.cs    манифест набора модов
                         Net.cs            HTTP-сервер на TcpListener + клиент
                         P2P.cs            трекер, P2P-узел, загрузчик чанков
                         Theme.cs          тёмная тема, лог
                         TrayIcon.cs       свёртывание в трей, общее для обоих exe
                         Proc.cs           процессы, обёртка SteamCMD
                         ServerKit.cs      telnet, контроллер сервера, разбор лога
                         ServerConfig.cs   редактор serverconfig.xml
                         Backup.cs         бэкапы с ротацией
                         Scheduler.cs      ежедневные задачи
  src\Server\          WolfServer  — управление сервером и раздача модов
  src\Launcher\        WolfLauncher — клиентский лаунчер
  tests\               SelfTest, NetTest, BackupTest
  dist\                результат сборки (готово к раздаче)
  bin\                 только тестовые exe
```

## Сборка

```
WolfSuite\build.bat
```

Аргумент `nopause` — без остановки в конце (для скриптов).

Баннер в шапке лаунчера — `assets\banner.jpg` (1000×199), фон кнопки «Играть» — `assets\blood.png`
(540×92, капли крови). Оба встраиваются в exe как ресурсы (`/resource` в `build.bat`),
внешних файлов игроку не нужно. Чтобы поставить другие картинки: заменить файлы в `assets\`
и пересобрать.

## WolfServer — управление сервером

| Вкладка | Что делает |
|---|---|
| Обзор | состояние, запуск/стоп/перезапуск, обновление через SteamCMD, ссылка на группу ВК |
| Живой лог | подсветка `ERR` / `EXC` / `WRN`, фильтр «только проблемы», счётчики, автоскролл |
| Чат | лента игрового чата (из лога сервера) + отправка сообщения всем игрокам через telnet |
| serverconfig.xml | правка по группам (основное, сеть и слоты, мир, админ-порты) + сырой текст |
| Моды и раздача | скан Mods, публикация набора, HTTP-раздача, P2P-сид, список пиров |
| Игроки | онлайн, кик/бан/разбан, телепорт, сообщение в чат (telnet) |
| Бэкапы | ручной бэкап, список, восстановление, удаление, ротация |
| Расписание | ежедневные перезапуск / бэкап / сообщение с предупреждением в чат |
| Настройки | пути, порты раздачи, лимиты хранения, автоперезапуск, автопереподключение консоли |

Подробности — в `dist\WolfServer\README.txt`.

## WolfLauncher — клиентский лаунчер

- адрес сервера строкой (`http://хост:8775`), манифест читается автоматически;
- список модов с версиями и статусом «актуален / нужно обновить»;
- докачиваются только отсутствующие чанки;
- чанки с сервера качаются **12 потоками с переиспользованием соединений**: без пиров
  загрузка упиралась в задержку одного запроса и ехала в разы медленнее канала;
- пиры и сервер работают **одновременно**: сервер тянет основную часть, до четверти чанков
  забирают до трёх пиров параллельно (раньше пиры пробовались до сервера и тормозили старт);
- лишние моды удаляются (папка `disabled_mods` не трогается);
- запуск игры: `-useEAC=0/1`, `-skipintro`, `-skipnews`, доп. параметры;
- автопроверка обновлений по таймеру;
- кнопка «Играть» сначала сверяет набор с сервером и докачивает недостающее — без актуальных
  модов игра не запускается (как в ModSync); если сервер недоступен, лаунчер спросит,
  запускать ли игру без сверки;
- автоподключение к серверу при нажатии «Играть» (клиентский мод `ZZZ_WolfAutoConnect`);
- сворачивается в трей (и уходит туда сам после запуска игры);
- автозапуск вместе с Windows включён по умолчанию — снимается галочкой в настройках;
- кнопка **«Группа ВК»** → `https://vk.ru/7daystodieworld`.

Подробности — в `dist\WolfLauncher\README.txt`.

## Автоподключение к серверу

В 7 Days to Die **нет** ключа командной строки для автовхода на сервер (проверено по сборке
игры: ключи есть только у `skipintro`, `noxui` и т.п.). Поэтому автовход сделан клиентским
модом `Mods\ZZZ_WolfAutoConnect`:

```
лаунчер «Играть»
   -> пишет %APPDATA%\7DaysToDie\WolfAutoConnect.xml  (IP + порт игры, Enabled=true)
   -> запускает 7DaysToDie.exe
        -> мод ловит ModEvents.MainMenuOpened
        -> ConnectionManager.Instance.Connect(GameServerInfo)
        -> гасит Enabled=false, чтобы прямой запуск игры из Steam не тянул на сервер
```

- адрес берётся из поля «Адрес сервера» (порт игры — из `/server.json`, поле `port`);
- мод молча ничего не делает, если файла нет или в нём `Enabled` не `true`;
- выключить автовход: удалить папку `Mods\ZZZ_WolfAutoConnect` на клиенте (или поставить
  `Enabled=false` в `WolfAutoConnect.xml`);
- исходник мода — `mod\AutoConnect\WolfAutoConnect.cs`, сборка — `mod\AutoConnect\build_mod.bat`
  (компилируется против сборок игры, путь задаётся переменной `GAME`).

## Как раздаются моды

Содержимое папки Mods режется на чанки по 1 МиБ. Имя чанка — его SHA-256, поэтому
одинаковые файлы и одинаковые части больших архивов хранятся и передаются один раз.

```
сервер:  Mods\  --(хэширование)-->  chunk store  -->  manifest.json
                                                          |
клиент:  GET /manifest.json  <----------------------------+
         GET /chunk/<sha>    (HTTP, работает всегда)
         TCP <пир>:<порт>    (P2P, разгружает сервер)
```

- Трекер на серверном туле: `/announce`, `/peers`, `/status`.
- P2P-узел есть в обоих приложениях: сервер — сид, каждый клиент раздаёт скачанное.
- Каждый чанк проверяется по хэшу до записи — подделанные данные отвергаются.
- HTTP-сервер на `TcpListener`, а не `HttpListener`: последний требует резервирования
  URL (права администратора) для прослушивания не-loopback адреса.

```
bin\SelfTest.exe     JSON, разбор реального serverconfig.xml, чанковое хранилище, манифест
bin\NetTest.exe      сквозной цикл: манифест → трекер → P2P → HTTP → сборка файлов

```

## Порты

| Порт | Назначение | Проброс |
|---|---|---|
| 8775 | HTTP: манифест, чанки, трекер | нужен, если игроки не в локальной сети |
| 6893 | P2P между игроками | не обязателен |
| 26900 | игровой сервер | нужен |
| 8081 | telnet (только локально) | нет |

## Замечания по эксплуатации

- Для управления игроками включите в `serverconfig.xml`: `TelnetEnabled=true`.
  Пустой пароль оставляет telnet на loopback — для локального тула это и нужно.
- Раздача модов работает без прав администратора.
- `UserDataFolder` в конфиге учитывается при поиске папки сохранений.
